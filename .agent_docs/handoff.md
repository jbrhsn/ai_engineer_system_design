# Project Handoff

## Project Summary

**AI System Design for AI Engineers** is a Markdown-only learning repository for AI/ML system design interview preparation at the Applied AI Engineer level — designing and defending production-grade agentic AI, RAG, and multi-agent architectures with a security-first, evaluation-first lens. It targets an engineer with 4 years of hands-on production experience (LangGraph multi-agent systems, RAG pipelines, FastAPI/PostgreSQL) formalizing that experience for interviews, not learning AI from scratch. Time budget: ~20–30 hours across the curriculum.

**Key artifacts:**
- `AGENTS.md` — authoritative authoring rules (Content Depth Rules 1–9, file naming, template mapping). Read before populating any content.
- `templates/` — fully populated reference templates (`chapter-notes-template.md`, `interview-prep-template.md`, `section-index-template.md`, `capstone-template.md`, `authoring-guidelines.md`, `README.md`). Never edit these originals — copy their structure into target files.
- 5 numbered section folders (`01-`–`05-`), each with 2–3 chapter subfolders. Every chapter folder has topic notes plus an `interview-prep.md` numbered immediately after the last topic note.
- `capstone/project-brief.md` — integrative multi-agent platform design project.
- **All five curriculum sections are now fully authored** (sections 03 and 04 completed this session). The only remaining unpopulated stub in the numbered curriculum is `06-interview-questions-dump/question1.md` (a tracked empty placeholder, outside the curriculum) plus any not-yet-written forward-link targets.
- **Section 05, Chapter 4** (`04-cross-cutting-concerns-and-tradeoff-patterns/`) holds `00-golden-rulebook-cheatsheet.md` + nine pattern notes (`01`–`09`) + `10-interview-prep.md`, PLUS a `golden_rulebook_examples/` subfolder of five worked system-design questions grounded in the cheatsheet.

**Architecture:** Section → Chapter (two levels only, no module layer). Sections ramp: 01 classical systems refresher (light) → 02 LLM serving/RAG → 03 agentic/multi-agent (LangGraph) → 04 production concerns (OWASP security, eval, scaling) → 05 interview practice (delivery framework, worked case studies, mock question banks, cross-cutting trade-off patterns + golden-rulebook worked examples). Filenames are **locked** — real topic-specific kebab-case slugs were chosen deliberately since chapters may forward-link to not-yet-written stubs.

**Critical constants:** lowercase-hyphen naming; no thought-leadership files; no lab files; interview-prep is the only auxiliary file type. Do not rename or renumber any file/folder — this breaks forward links.

## Quick Reference

- **No build system, no tests** — this is a pure Markdown content repo.
- **Authoring source of truth:** `AGENTS.md` at repo root — read before populating any stub.
- **Template files (reference-only, never edit):** `templates/chapter-notes-template.md`, `templates/interview-prep-template.md`, `templates/section-index-template.md`, `templates/capstone-template.md`, `templates/authoring-guidelines.md`.
- **Stub marker:** unpopulated files contain exactly `<!-- stub: populate using templates/ -->` — intentional, not missing content.
- **Skills for authoring:** `author-chapter` (researches live sources, follows `chapter-notes-template.md` + Content Depth Rules 1–9, runs a quality gate); `generate-practice-exam` (grounds questions in authored content only).
- **Orchestrator pattern that works (used for sections 03/04):** delegate one file per `executor` subagent; pass the exact target path, the correct template, `AGENTS.md` rules, a **house-quality reference file** to match depth/tone (`03-.../01-agent-design-patterns/01-react-and-tool-calling-agent-fundamentals.md`), detailed topic framing with the mandatory sections spelled out, and an explicit instruction to WRITE in-run and **webfetch-verify every framework detail + Further Reading URL**. Run subagents in parallel; dispatch each section's `README.md` **last** so it summarizes real content. If a subagent's reply is truncated, verify its file directly (grep sections/anti-patterns/self-checks; curl the links).
- **Standard chapter-notes template order (11 blocks):** H1 + `**Section:** … | **Est. time:** … | **Interview relevance:** …` line → TL;DR (bolded "The one thing to remember") → ELI5 (structural analogy) → Learning Objectives → Visual Overview (2–4 ASCII diagrams, **no language tag** on those fences) → Key Concepts (each: what/how-mechanism/where-in-real-systems) incl. Key Parameters table + Worked Example (Given + Steps 1–5) → Implementation (≥2 snippets, ≥1 `# Anti-pattern:` + corrected) → Common Pitfalls (3-part bullets) → Key Definitions → Summary → Self-Check (exactly 5, Q1 recall→Q4–5 trade-off, ≥1 multi-select "Which TWO", answers in `<details>`) → Further Reading (official only).
- **Interview-prep template (7 blocks):** Core Conceptual Questions table (`Question | Key points | Common weak-answer trap`) → Applied/Scenario Questions → System Design/Architecture Questions → Vocabulary That Signals Expertise → Vocabulary That Signals Weakness → STAR Answer Frame → Red Flags. No Further Reading / code snippets required.
- **`golden_rulebook_examples/` house format:** H1 → "grounded in `../00-golden-rulebook-cheatsheet.md`" intro → `## The Question` (Context + `**Requirements:**` + `**Your task:**` numbered) → `## Worked Answer` (clarify/SLO opener + `### Answer` one `####` per task + ≥1 ```text ASCII diagram) → `### How the cheatsheet was used` → `## Cheatsheet elements referenced`.
